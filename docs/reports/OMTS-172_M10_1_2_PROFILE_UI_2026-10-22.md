# OMTS-172 M10.1–M10.2 — Account hub and profile presentation

## Requirement evidence

Jira OMTS-172 requires the Mobile SCR-05 profile section with the same fields,
verification flow and messages as Web. SRS UC05 makes display name, email and
phone personal fields; username and role/scope are read-only. A new contact must
not replace the current value before UC08 verification succeeds.

## Implemented

- Added a pure display-name validation contract with trimmed output and a
  required-field error.
- Added typed account, contact and access-summary presentation contracts.
- Added a controlled account/profile screen with no default user name,
  cooperative name or role fixture.
- Rendered username/account code/type as read-only text and multiple supplied
  zone–role summaries as independent lines.
- Kept direct Save scoped to display name. Email and phone each have a separate
  action that a future controller routes into UC08.
- Added contact verification statuses, account actions for password,
  notifications and logout, plus typed MSG10 feedback.

## Why contact changes are separate

```text
display-name edit -> profile save -> current profile refresh

email/phone change -> enter candidate -> UC08 challenge -> verify
                   -> backend replaces current contact -> profile refresh
```

This prevents an unverified candidate from being displayed or used as the
account's current contact. It also preserves the previous verified identifier
when code delivery or verification fails.
