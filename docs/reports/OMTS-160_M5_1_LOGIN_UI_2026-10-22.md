# OMTS-160 — M5.1 login contract and SCR-03 presentation

## Sources reviewed

- Jira OMTS-160: Mobile login, forced-password/phone-verification gates, permission-aware app stack and Forgot Password entry.
- SRS UC02/SCR-03: username/verified phone/email identifier, required password, recovery, Trader registration and public QR access.

## Outcome

The auth feature now has a pure login-form validator and a controlled production `LoginScreen`.

The validator trims only the identifier, preserves the password exactly and checks only required fields. It deliberately does not apply the new-password policy to login because existing and temporary credentials must be evaluated by the backend.

The screen provides identifier/current-password autofill, inline field errors, generic feedback, local pending state and four explicit actions: Login, Forgot Password, Trader Registration and Public QR Lookup.

## Security and architecture

- Credentials are never logged or persisted by these components.
- MSG12 remains generic and does not identify whether the account or password was wrong.
- The screen emits callbacks and does not create a session, choose a post-login gate or open the app stack.
- `clientType`, token storage/refresh and gate priority remain blocked on the existing backend contract decisions.

## Verification evidence

Three form tests and four screen tests cover exact credential normalization, required fields, absence of new-password policy, autofill configuration, all navigation actions, generic failure copy and pending lock. Targeted Jest, strict TypeScript, Expo lint and whitespace checks passed.
